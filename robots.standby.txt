# ── 备用 robots.txt：本站线上那份没有换，这份只是备着 ──────────────────
#
# 为什么不换（她的决定，2026-10-04）：现在整站托管在 GitHub Pages，所以不用防爬虫。
# 这条理由站得住的地方是具体的，不是"Pages 帮你挡了"：
#   ① GitHub Pages 是静态托管，抓取打在 GitHub 的边缘节点上，不是自己的服务器，
#      AI 抓取器抓得再凶也不会让她多掏一分钱、不会把站抓下线。防爬虫的实际收益
#      （省带宽、防过载）在这个托管形态下不存在。
#   ② 这个仓库本身是公开的（api.github.com 查得 private:false），正文的 markdown
#      原文就跟着 source/_posts 一起可读。robots.txt 是给守规矩的抓取器看的声明，
#      不是访问控制；想拿原文的人，仓库那条路比 robots.txt 直接得多。
#   ③ 换来换去只有代价没有收益的一条：`User-agent: *` 全站放行正是 Google/Bing
#      收录需要的状态，改成屏蔽版会把搜索收录一起牵动。
#
# 这份文件的用处：如果哪天换到自建服务器 / 开始有带宽成本 / 想认真退训练抓取，
# 就把整个文件覆盖到 themes/mustom/source/robots.txt（主题那份现在是 13 字节的
# `User-agent: *`，站点根 source/ 下没有另一份），然后 hexo clean && hexo generate，
# 结果落在 public/robots.txt。下面"第一组"是解开注释、拿来即用的状态。
#
# 本文件放在仓库根目录：hexo 只拷 source/ 和主题 source/，它不会被发布出去，
# 线上生效的仍是主题那份放行版。
#
# 分级口径与逐字引文：S:\apps\llm\agentwork\robots-ai\官方口径核对.md
#   A = 归属方自己的文档页里逐字出现该名字，并且厂商自己明说它用于 AI 抓取/模型训练；
#   B = 名字在厂商页里有，但厂商把用途说成搜索收录、链接预览、混合爬虫或用户触发的访问；
#   C = 本地厂商侧查不到实据，只在 nixCraft 或第三方 SEO 清单里出现过。
# nixCraft 原文（她存到下载目录那份 .htm 的逐字誊本）：同目录 nixcraft-原文条目.md
# 与那份清单的逐条差异：同目录 对照.md

# ── 基线：全站仍对正规搜索引擎放行 ────────────────────────────────
User-agent: *
Allow: /

# ── 第一组：A 级 6 条，厂商自己写明"用于 AI 抓取/训练" ──────────────
# 屏蔽它们的代价只是"少一份被训练的可能"，不动任何搜索收录。

# OpenAI 训练类抓取。依据 https://platform.openai.com/docs/bots
# 原文："GPTBot is used to make our generative AI foundation models more useful and
# safe. It is used to crawl content that may be used in training our generative AI
# foundation models. Disallowing GPTBot indicates a site's content should not be
# used in training generative AI foundation models."
# 官方同时说明这一项与 OAI-SearchBot 相互独立，关掉它不影响 ChatGPT 搜索收录。
User-agent: GPTBot
Disallow: /

# Google 的训练令牌。依据
# https://developers.google.com/search/docs/crawling-indexing/google-common-crawlers
# 原文："Google-Extended is a standalone product token that web publishers can use
# to manage whether content Google crawls from their sites may be used for training
# future generations of Gemini models…"；同段："Google-Extended does not impact a
# site's inclusion in Google Search nor is it used as a ranking signal."
# 同页另一句给这条加了一个限制："Google-Extended doesn't have a separate HTTP
# request user agent string. Crawling is done with existing Google user agent
# strings; the robots.txt user-agent token is used in a control capacity."
# 中译：它没有独立的 HTTP 请求 UA 串，实际抓取用既有的 Google UA，这个令牌只起控制作用。
# 所以按 UA 写日志过滤或防火墙规则拦不到它，robots.txt 是唯一对它生效的一层。
User-agent: Google-Extended
Disallow: /

# Google 的另一条：站点所有者自己为构建 Vertex AI Agents 发起的那类抓取。
# 同页原文："Crawling preferences addressed to the Google-CloudVertexBot user agent
# affect crawls requested by the site owner for building Vertex AI Agents. It has no
# effect on Google Search or other products."
# nixCraft 全文未出现这个名字。
User-agent: Google-CloudVertexBot
Disallow: /

# Anthropic 训练类抓取。依据
# https://support.anthropic.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler
# 原文："ClaudeBot helps enhance the utility and safety of our generative AI models
# by collecting web content that could potentially contribute to their training.
# When a site restricts ClaudeBot access, it signals that the site's future materials
# should be excluded from our AI model training datasets."
# 同页三句与写法直接相关："Anthropic's Bots respect 'do not crawl' signals by
# honoring industry standard directives in robots.txt."；
# "To limit crawling activity, we support the non-standard Crawl-delay extension to
# robots.txt."；
# "Alternate methods like blocking IP address(es) … may not work correctly or
# persistently guarantee an opt-out, as doing so impedes our ability to read your
# robots.txt file."——封 IP 反而可能让退出失效，因为它因此读不到你的 robots.txt。
User-agent: ClaudeBot
Disallow: /

# Amazon 的训练相关抓取。依据 https://developer.amazon.com/amazonbot
# 原文："Amazonbot is used to improve our products and services. This helps us
# provide more accurate information to customers and may be used to train Amazon AI
# models."
# 同页承诺："Automated crawling from these listed user agents respects the Robots
# Exclusion Protocol, honoring the user-agent and the allow/disallow directives.
# …When a file can't be fetched, they will behave as if it does not exist."
# 最后一句的意思是：robots.txt 取不到时按"没有这个文件"处理，所以屏蔽要稳就得让
# 这个文件始终能被取到——这也是"改不改这份文件"值得单独想一次的原因。
User-agent: Amazonbot
Disallow: /

# Apple 的退训练开关。依据 https://support.apple.com/en-us/119829
# 原文："Web publishers can opt-out from having their content used to train
# generative foundation models by disallowing Applebot-Extended in the robots.txt
# file."
# 注意：只 disallow 这一个，不要 disallow `Applebot`——后者管 Siri/Spotlight 的
# 搜索收录（apple.com/legal/privacy："To power features such as search … Apple uses
# Applebot, a web crawler"）。nixCraft 那份清单写的正是 `Applebot`，这是整份清单里
# 最容易搞错的一条；Apple 给的纯退训练令牌 nixCraft 也没有。
User-agent: Applebot-Extended
Disallow: /
