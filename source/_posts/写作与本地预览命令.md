这台机器上没有 Node，构建工具是 Deno（`C:\Users\takomi\.deno\bin`，已在用户 PATH 里）。Hexo 本身是个 npm 包，Deno 能直接跑 npm 包的命令行，所以不需要 Node 也能生成和预览。

在 Git Bash 里，于仓库根目录执行：

```bash
cd /s/apps/llm/agentwork/blog
alias hexo='deno run -A npm:hexo'   # 每次开一个新终端先敲一次

hexo new "文章标题"        # 生成 source/_posts/文章标题.md
hexo server              # 本地预览，http://localhost:4000
hexo clean && hexo generate   # 清缓存并静态生成到 public/
```

## 为什么不用 deno install

`node_modules/` 是当初用 npm 装的扁平结构，Deno 直接读它跑得很好，构建产物和 Node 构建逐字节一致（只差模板里的 `?t=` 缓存时间戳）。

但**别在这个目录里跑 `deno install`**。实测两种链路都会把依赖装坏：

| 命令 | 结果 |
| --- | --- |
| `deno install`（默认 isolated 链路） | 包全落在 `node_modules/.deno/<pkg>/node_modules/…`，顶层没有条目，hexo 的 `require('hexo-cli')`、`require('bluebird')` 全部 Cannot find module |
| `deno install --node-modules-linker=hoisted` | 顶层 179 个包齐了，但 Deno 会按自己的可达性分析裁剪包内文件：`prismjs` 只剩 `CHANGELOG.md` 和 `components/`，根目录的 `components.js` 被裁掉，`hexo-util/dist/prism.js` 一 require 就炸 |

真要重装依赖，解压仓库同级的 `_bak/blog_node_modules_npm.tar.gz`（npm 装的完整备份），或者干脆不管——线上构建是 GitHub Actions 上用真 Node + `npm ci` 跑的，本地依赖坏了也不影响上线。

## 改了东西怎么上线

`git add -A && git commit && git push` 之后由 GitHub Actions 构建并部署到 Pages，不需要本地 `hexo generate` 的结果上传。本地 `hexo server` 只为看效果。

## 依赖清单

| 包 | 版本 | 作用 |

| hexo | 8.x | 静态站点生成器 |

| hexo-server | 3.0.0 | `hexo server` 的本地服务 |

## 目录约定

- `source/_posts/` 一篇文章一个 md 文件，文件名就是标题
- `source/about/index.md` 是「关于」页，front-matter 里 `layout: page` 且 `name` 要和文件夹名一致，主题的 page 部件才认它
- `source/` 下任何非 md 文件（`live2d/`）会被原样拷进站点根目录，这就是自托管资源的放法
- `scaffolds/` 是新文章的模板
