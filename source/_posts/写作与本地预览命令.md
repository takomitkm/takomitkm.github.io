本机没装系统级 Node，用的是解压在 `S:\apps\llm\node\node-v22.20.0-win-x64` 的便携版：不进 PATH、不写注册表。所以每条命令前要先把它临时挂到 PATH 上。

在 Git Bash 里，于仓库根目录执行：

```bash
export PATH="/s/apps/llm/node/node-v22.20.0-win-x64:$PATH"

npm install          # 只有第一次、或换依赖时
hexo new "文章标题"  # 生成 source/_posts/文章标题.md
hexo server          # 本地预览，http://localhost:4000
hexo clean && hexo generate   # 清缓存并静态生成到 public/
```

## 改了东西怎么上线

`git add -A && git commit && git push` 之后由 GitHub Actions 构建并部署到 Pages，不需要本地 `hexo generate` 的结果上传。本地 `hexo server` 只为看效果。

## 依赖清单

| 包 | 版本 | 作用 |
| --- | --- | --- |
| hexo | 8.x | 静态站点生成器 |
| hexo-renderer-ejs | 2.0.0 | 渲染主题的 `.ejs` 模板 |
| hexo-renderer-stylus | 3.0.1 | 编译主题的 `.styl` 样式 |
| hexo-renderer-markdown-it | 7.1.1 | 把 Markdown 文章转成 HTML |
| hexo-generator-index / archive / category / tag | 4 / 2 / 2 / 2 | 首页、归档、分类、标签四类列表页 |
| hexo-generator-feed | 4.0.0 | RSS |
| hexo-server | 3.0.0 | `hexo server` 的本地服务 |

## 目录约定

- `source/_posts/` 一篇文章一个 md 文件，文件名就是标题
- `source/about/index.md` 是「关于」页，front-matter 里 `layout: page` 且 `name` 要和文件夹名一致，主题的 page 部件才认它
- `source/` 下任何非 md 文件（`live2d/`、`shiftnav/`）会被原样拷进站点根目录，这就是自托管资源的放法
- `scaffolds/` 是新文章的模板
